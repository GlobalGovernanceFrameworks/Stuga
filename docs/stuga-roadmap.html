📍 Nuläge (v1.1.1 - Januari 2026)

Status: Pilot-redo
Färdigställd: 11 januari 2026

Implementerade funktioner:

  • Grannupptäckt: GPS-baserad upptäckt inom 500m
  • Resursdelning: 8 kategorier (mat, värme, verktyg, transport, kunskap, boende, första hjälpen, annat)
  • Brådskesystem: Resurser prioriteras efter utgångstid
  • Hearts-ekonomi: Tacksägelsesystem för att bygga reciprocitet
  • Offline-resiliens: Fungerar utan internet, synkar automatiskt
  • Privacy-by-design:
    • Burner profiles (display names)
    • Kontaktförfrågningar (samtycke krävs)
    • Fuzzy distance (anti-stalking)
    • Blockeringsfunktion
  • Bluetooth mesh: Grundläggande implementering för peer-to-peer upptäckt

Teknisk stack: React Native, Firebase, SQLite, Expo

Geografisk begränsning: Upplands Väsby kommun

Target: Liten pilot våren 2026 med 20-50 användare

🧭 Utvecklingsfilosofi: Spiral Dynamics

Stugas utveckling följer Spiral Dynamics-ramverket för att bygga sociala system som matchar användarnas mognad och behov:

🟣 PURPLE (Tribe)
🔴 RED (Power)

🟠 ORANGE (Achievement)
🟢 GREEN (Community)

Aktuell fas: PURPLE - Tribal Trust

Fokus på att bygga grundläggande tillit mellan grannar genom:

  • Progressiv information disclosure (känner man varandra → mer data synligt)
  • Samtycke och kontroll över personlig information
  • Reputation genom Hearts-systemet
  • Små, lokala communities (grannar du kan gå till)

Version 1.2 - Post-Pilot (Q2 2026)

Purple (Tribe) - Förbättringar
Planerad: April-Juni 2026

📊 Förbättrad Reputation

  • Reliability score: Kombination av Hearts och faktisk hjälp given
  • Completion rate: Hur ofta någon följer upp på erbjudanden
  • Response time: Hur snabbt någon svarar på kontaktförfrågningar
  • Badges: "Pålitlig granne", "Snabb respons", "Givmild hjälpare"

👥 Trust Circles

  • Gradual disclosure: Mer data synligt baserat på relation-depth
  • Neighbor endorsements: "Anna vouches for Sven"
  • Mutual friends: "Du och Maria har 3 gemensamma kontakter"
  • Trust levels: Stranger → Acquaintance → Friend → Trusted

🔔 Förbättrade Notifikationer

  • Push notifications: Brådskande resurser, kontaktförfrågningar
  • Customizable alerts: Välj vilka kategorier du vill få notiser om
  • Quiet hours: Ingen störning nattetid (förutom emergencies)

📍 Förbättrad Location

  • Availability tracking: "Senast sedd för 2 timmar sedan"
  • Auto-away status: Sätt som "borta" automatiskt efter X dagar inaktivitet
  • Location history: "Anna är oftast hemma mellan 18-20"

🔍 Förbättrad Sökning

  • Saved searches: "Generatorer inom 200m"
  • Filter kombinationer: Mat + Brådskande + <100m
  • Match notifications: "Någon erbjuder det du söker!"

Version 1.5 - Leadership & Coordination (Q3 2026)

🔴 Red (Power) - Ledarskap
Planerad: Juli-September 2026

👑 Block Captains (Kvarterschefer)

  • Designated leaders: Frivilliga som koordinerar sitt kvarter (50-100 personer)
  • Coordination dashboard: Översikt över alla resurser och behov i sitt område
  • Emergency broadcast: Skicka meddelande till alla i sitt kvarter
  • Resource allocation: Hjälp till att matcha behov med erbjudanden
  • Status reporting: Rapportera läget i sitt kvarter till kommun

🚨 Emergency Mode

  • Crisis declaration: Block captain aktiverar "crisis mode"
  • Priority escalation: Alla får notis om kritiska behov
  • Resource claiming: "Jag hanterar den här förfrågan"
  • Status updates: Löpande uppdateringar om läget
  • Check-in system: "Är alla okej?" med snabb respons

📊 Coordination Tools

  • Resource inventory: Totalt antal generatorer, ficklampor, etc. i området
  • Gap analysis: "Vi har 5 generatorer men 12 som behöver"
  • Distribution planning: "Generator till familj med spädbarn först"
  • Volunteer coordination: "Vem kan köra? Vem kan laga mat?"

🔐 Block Captain Accountability

  • Confidence Voting: Quarterly trust votes from circle
  • Emergency Recall: 5+ neighbors trigger immediate vote
  • Activity Transparency: Public captain metrics
  • Automatic Rotation: Failed confidence → new election
  • Anti-Tyranny: No captain can serve >2 consecutive terms

🛡️ Stage Red Mitigation: Prevents power concentration while maintaining leadership structure. Balances Purple (trust) with Blue (rules).

🏗️ Infrastruktur-evolution: CivicBase (2027+)

Från Firebase till P2P-infrastruktur

Status: Strategisk vision, beroende av Vinnova/MSB-finansiering

Tidslinje: Migration planerad för v2.0+ (2027)

Nuvarande Arkitektur (v1.x - Pilot-fas)

  • Backend: Firebase (Firestore, Authentication, Cloud Functions)
  • Offline: SQLite-baserad kö för transaktioner
  • Sync: Firestore real-time synkronisering
  • Rationale:
    • ✅ Snabb utveckling och iteration
    • ✅ Låg initial kostnad
    • ✅ Fokus på användarbehov, inte infrastruktur
    • ✅ Bevisar koncept innan stor investering

Framtida Arkitektur: CivicBase P2P Platform

CivicBase - Offline-First P2P Infrastructure
Beroende på: Distributed systems expert + Vinnova/MSB finansiering

🎯 Varför CivicBase?

  • Data sovereignty: All data i Sverige på svenska enheter
  • Total offline-resiliens: Mesh networking när internet är nere
  • Oberoende: Ingen dependency på molntjänster (AWS, Google, etc.)
  • Totalförsvar: Uppfyller MCF:s krav på kritisk infrastruktur
  • Privacy-by-design: Agent-centric data model, end-to-end kryptering

🔧 Teknisk Implementation

  • Peer-to-peer networking: libp2p (beprövad teknologi från IPFS/Filecoin)
  • Mesh networking: Bluetooth/Wi-Fi Direct för lokal kommunikation
  • Offline sync: Vector clocks + conflict resolution
  • Kryptering: AES-256-GCM (data), Ed25519 (signatures)
  • GDPR-compliant: Data minimization, user deletion, no central database

📋 Migrations-plan (v1.x → v2.0)

  • Fas 1: CivicBase-plattform utvecklad parallellt (Vinnova-finansierad)
  • Fas 2: Stuga-datamodell porteras till agent-centric schema
  • Fas 3: Gradvis migration av användare (dual-stack period)
  • Fas 4: Firebase-backend deprecerad när alla migrerat
  • Tidsram: 6-12 månader med distributed systems expert

💰 Budget & Förutsättningar

  • Distributed systems consultant: 800,000 SEK (4 månader)
  • Security audit: 400,000 SEK (penetration testing)
  • Lead developer time: 600,000 SEK (migration + integration)
  • Testing & deployment: 300,000 SEK (pilot miljö, documentation)
  • Total budget: ~2,100,000 SEK (CivicBase core + Stuga migration)
  • Finansieringskällor: Vinnova, MSB/MCF, Region Stockholm

Varför Inte CivicBase Från Början?

Pragmatisk approach:

  • Komplexitet: P2P mesh networking, offline reconciliation, vector clocks kräver expert-nivå kunskap
  • Risk: Bygga avancerad infrastruktur INNAN behovet är bevisat = stor risk
  • Timing: Firebase låter oss validera användarbehov snabbt (3 månader vs 18 månader)
  • Finansiering: "Vi har 500 aktiva användare" ger starkare Vinnova-ansökan än "cool teknologi"
  • Fokus: Piloten handlar om social dynamik, inte teknik-stack

Strategi: Bevisa värdet först (Stuga på Firebase), sedan bygg rätt infrastruktur (CivicBase) med finansiering och expert-hjälp.

Stuga som CivicBase Reference Implementation

  • Första produktions-app: Stuga blir reference implementation för CivicBase
  • Real-world testing: Valideringsdata från faktisk pilot (inte teoretisk design)
  • Use cases proven: Hearts currency, resource sharing, contact requests - allt testat live
  • Municipal integration: Upplands Väsby-piloten visar hur kommuner kan använda plattformen
  • Platform foundation: Stuga + CivicBase → mall för andra kommunala tjänster

Beyond Stuga: CivicBase Ecosystem

När CivicBase-plattformen är färdig blir Stuga en av många applikationer som drar nytta av offline-resilient infrastruktur:

  • TAK-405: Transit wellness (Stockholm SL)
  • DPOP: Political organizing platform
  • DiDiS: Distributed digital identity
  • Healthcare records: Patientjournaler med offline-kapacitet
  • Elder care coordination: Fungerar i landsbygd med dålig uppkoppling
  • Emergency response: Mesh networking för grannkoordinering

Teknisk Realitet Check

⚠️ Detta är svår teknologi

CivicBase kräver expert-nivå kompetens inom:

  • Distributed systems (P2P, consensus, CAP theorem)
  • Cryptographic protocols (end-to-end encryption, signing)
  • Conflict resolution (vector clocks, CRDTs, operational transforms)
  • Network engineering (NAT traversal, mesh routing, topology optimization)
  • Mobile development (cross-platform, battery optimization, background sync)

Därför budgeterar vi 800K för distributed systems consultant. Detta är inte något man "lär sig på YouTube" - det är flera års specialiserad erfarenhet.

Ärlig bedömning: Som solo-utvecklare kan jag inte bygga CivicBase ensam på rimlig tid. Men jag kan bygga Stuga på Firebase NU, bevisa behovet, få finansiering, och sedan anställa rätt expertis för CivicBase.

⚠️ Kritiska Risker

  • Tyrant Captain (Stage Red): Mitigated via confidence voting and term limits in V1.5+
  • Firebase → CivicBase Migration (V3.0): Requires "Sovereignty Ceremony" UX to frame as upgrade, not disruption
  • Pilot Dependency: V1.x success critical for V2.x+ funding

🔮 Långsiktig Vision (2027+)

Kärnprinciper

  • Decentraliserad resiliens: Fungera helt utan centraliserad infrastruktur
  • Privacy-first: Minimera data, maximera kontroll
  • Progressive enhancement: Börja enkelt, väx med användarnas mognad
  • Municipal coordination: Komplettera, inte ersätta, officiell krisberedskap
  • Open source: Transparent, granskningsbar, community-driven

Tekniska Milstolpar

  • P2P Mesh Network: Fullständig Bluetooth mesh för offline-kommunikation
  • LoRa Integration: Långdistans-kommunikation utan internet (10+ km)
  • Satellite backup: Starlink/Iridium för remote områden
  • Voice messages: Offline voice-to-text för äldre
  • QR-kod sharing: Dela resurser utan app (pappersutskrift)
  • Multi-municipality: Expandera till andra kommuner i Sverige

Integration med Bredare Ekosystem

  • MSB koppling: Integration med Myndigheten för samhällsskydd och beredskap
  • SOS Alarm: Nödläge-knapp som kontaktar både grannar och SOS
  • 1177: Medicinsk rådgivning och första hjälpen-info
  • Civilförsvarsförbundet: Utbildningar och övningar
  • Grannsamverkan: Integration med befintliga grannsamverkansgrupper

Forsknings- och Utvecklingsområden

  • Care Economy: Stuga som forskningsplattform för lokal ekonomi utan pengar
  • Trust algorithms: Automatisk detection av pålitlighet baserat på beteende
  • Resource optimization: AI för att matcha resurser med behov optimalt
  • Behavioral science: Nudging för ökad deltagande och reciprocitet
  • Network theory: Förstå hur tillit sprids i sociala nätverk

📊 Success Metrics

Kort Sikt - Stuga Pilot (6 månader)

  • 100+ aktiva användare i Upplands Väsby
  • 80% av användare loggar in minst 1 gång/vecka
  • 50+ resurser delades per månad
  • 500+ Hearts-transaktioner totalt
  • 90% user satisfaction (survey)
  • Målsättning: Bevisa att grannsamverkan + Hearts fungerar i praktiken

Medellång Sikt - Expansion (12 månader)

  • 500+ aktiva användare i Stuga
  • 10+ block captains aktiva
  • Minst 1 verklig kris-situation hanterad framgångsrikt
  • Expansion till 2-3 angränsande kommuner
  • Partnership med Upplands Väsby kommun etablerat
  • Vinnova/MSB ansökan beviljad: Finansiering för CivicBase secured

Lång Sikt - CivicBase Platform (24+ månader)

  • Stuga: 10,000+ användare nationellt i 20+ kommuner
  • CivicBase: Platform färdig och säkerhetsauditerad
  • Migration: Stuga migrerad från Firebase till CivicBase
  • Ecosystem: 2-3 andra appar byggda på CivicBase (TAK-405, DPOP, etc.)
  • Integration: MSB och SOS Alarm kopplingar etablerade
  • Forskning: Vetenskapliga publikationer om care economy-data
  • Hållbarhet: Self-sustaining community + konsultintäkter
Milestolpe-logik:
  1. Stuga pilot bevisar socialt behov (grannsamverkan + Hearts)
  2. Framgångsrik pilot ger trovärdighet för Vinnova/MSB-ansökan
  3. Vinnova-finansiering bygger CivicBase infrastruktur
  4. Stuga migreras till CivicBase som reference implementation
  5. CivicBase blir plattform för nationell skalning
